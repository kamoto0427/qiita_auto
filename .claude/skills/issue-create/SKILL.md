## 前提
このスキルは `/plan` スキルで要件定義・詳細設計の承認が済んだ後に呼ばれることを想定している。
ヒアリングや要件整理はすでに完了しているため、渡された設計内容をもとにそのまま Issue を作成する。

## 手順
1. 委任メッセージまたは会話コンテキストから以下を確認する：
   - 機能名・変更内容の概要
   - 変更が必要なファイルと実装方針（`/plan` の詳細設計書から引用）
2. 不明点がある場合のみ AskUserQuestion で確認する（原則ヒアリング不要）
3. 以下の内容で Issue を作成する：
   - **タイトル**: `feat:` / `fix:` / `chore:` などのプレフィックスを付けた日本語タイトル
   - **本文**:
     - ## 概要（何をするか一言で）
     - ## 背景（なぜ必要か）
     - ## 機能詳細（具体的な仕様・箇条書き）
     - ## 変更ファイル（ファイル名と変更内容の表）
4. `gh issue create` コマンドでリポジトリ kamoto0427/qiita_auto に Issue を登録する
5. 作成された Issue の URL をユーザーに報告し、`/issue <番号>` で実装を開始できることを案内する
